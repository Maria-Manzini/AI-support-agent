This project demonstrated how Amazon Bedrock AgentCore and the Strands SDK can combine tools, retrieval, memory, code execution, and browser access into a practical customer-support agent. I chose AgentCore Gateway with MCP for order and refund operations because it allowed the agent to use existing business functions without embedding those operations directly into the model. I used the Bedrock Knowledge Base for product and policy information so that recommendations and support answers were grounded in controlled catalog data.

I chose AgentCore Memory for cross-session personalization because the agent needed to retain customer context between separate support interactions rather than relying only on the current conversation. This was particularly useful when the agent remembered that the customer preferred to be called Jane and preferred Wireless Headphones Pro. I also used Code Interpreter for loyalty calculations because financial arithmetic should be deterministic rather than dependent on the language model performing calculations correctly.

The implementation involved several challenges. The initial Python 3.13 environment failed because the available build lacked the `_sqlite3` module, so I recreated the environment with a working Python 3.13 installation through `uv`. Memory initially failed to persist information correctly across sessions; investigating the memory namespaces and adding an `AfterInvocationEvent` persistence callback resolved the issue. The browser integration initially produced a recursive `EventLoopException` with a maximum-recursion-depth error. I resolved this by explicitly instructing the agent to initialize a browser session before navigating. The loyalty agent test also initially used the default standard earning category, so I updated the system prompt to require `"device"` for electronics.

There were also data-quality limitations. The return-label tool returned a validity date of December 31, 2025, which was already expired during testing. The browser successfully retrieved the live Example Domain page, although its interpretation of the page heading was inaccurate. I documented these issues rather than hiding them.

For production, browser access and code execution should be tightly controlled because they introduce additional security, cost, and observability considerations. CloudWatch observability, explicit tool-use instructions, controlled knowledge sources, and deterministic calculations provide a foundation for operating the agent more reliably at scale.
